# New GHA passing-heartbeat native smoke

This is a new validation run, not a continuation or reinterpretation of older local smoke attempts. It builds two fresh Darwin arm64 Magpie binaries using Go 1.26.8: the complete R5 source accepted by run 43197186721 (5,697 files), and the pinned historical held-heartbeat source baseline (5,694 files). Both sources reconstruct from public Magpie commit 86254d4049cb6be4a2ccdab02edf0bd59860c603. SDK and compiler metadata and both resulting binary hashes are recorded. Neither result is claimed to equal a historical local binary.

fixture.py preserves nine exact R8 functions/classes: require, frame, prefix, half_frame, finish, Fake, Handler, codex_command and judge. FIXTURE-ORIGIN.json pins the original R8 source and each extracted source segment. Original fake data and judgment are unchanged. The new adapter supplies paths, isolation, subprocess/capacity cleanup and new artifact provenance.

The official Codex 0.164.0 archive is downloaded only on the disposable GHA runner. Its 101,767,166-byte archive must hash to aa8299c169d80111aac05543ad2621c9bdbedb9bc252c905fe3f5a5baf9a4142. The only extracted binary must be exactly 260,293,200 bytes and hash to d8990e3ee7acfbc26f91265b12a1a83f0fee40d0e0f8f1f40a37d4ec21f499cf. A mismatch is a hard failure; the newer R3 client is never substituted. Failed original download attempts remain historical evidence and are not considered successful here.

The baseline receives the comments fixture and must fail with the actual native SSE idle error, with no turn.completed. The candidate receives silent, comments and half-frame fixtures. Each sends PARTIAL_ first, then waits 20 seconds with a client stream idle limit of 18 seconds, then finishes PARTIAL_LOCAL_PASSING_COMPLETE and response.completed. Every candidate case requires exactly one fake request, one native turn.completed, the exact complete assistant message, no tool event and no client error. The supplier never emits ping events. This tests the passing-heartbeat path; R5 local-compaction coverage remains the already accepted separate Go gates. Cancel/gate behavior is not re-proven by these four cases.

A default-deny macOS sandbox allows the gateway only its own listener and fake upstream, and Codex only that owned gateway. It grants no fork, external network or credentials directory access. Real positive and negative Python probes run before either client path is accepted. Only exact read-only CoreFoundation preferences services/domain, uname MIBs and dynamic current-UID preference shared memory are allowed. No user preference is read or printed by the probes; they issue the same forced-key metadata queries and synchronize the domain.

HOME and CODEX_HOME are inherited unchanged. The GHA runner must initially have no Codex home at that inherited location. The controller creates one synthetic UUID in a newly owned directory, grants only that file's data read/write for the client's existing initialization requirement, compares content and identity after children are reaped, and deletes only that unchanged owned file and empty directory. An existing home, changed UUID, extra file or live child causes failure and preserves the scope for reconciliation. Logs/SQLite/XDG are private per case. Credentials from the parent environment are not copied.

Build/download/test admissions take two capacity samples, with a 30 GiB floor and 512 MiB build or 128 MiB smoke headroom. Running commands are monitored and only their owned child process groups may be stopped. Synthetic inputs/logs are preserved before cleanup; every failed attempt retains RESULT files. audit.py independently rereads case logs, hashes, client and two build receipts, probes, capacity samples, source integrity and native outcomes. Old run8/9, local collectors, production listeners and deployed services are never read or modified.

The workflow is restricted to ci/magpie-passing-smoke-20261112 and the exact package/workflow paths. Only public source patches, relative source manifests and synthetic harness inputs are published. The artifact includes newly built binaries and their acceptance records so reviewers can identify exactly what was tested. All execution is GHA-only; Python preparation tests use temp fixtures and never build, download, or run a model client.

## R2 entrypoint correction

The first real run 43214735533 verified the original official client and built both binaries successfully, but reached zero fake supplier requests. The build helper created a directory named data beside each Magpie binary; appdir.Config prioritizes that portable selector before XDG_CONFIG_HOME. The gateway therefore found no fixture model and returned 404. R2 names build-only XDG data xdg-data and refuses any data or .portable sibling (including symlinks) after build, before a case, and immediately before gateway start. No source patch, sandbox policy, fake frame, original R8 judgment or provider configuration changed.

The observed code-mode-host unavailable item is an existing startup diagnostic. Original R8 judgment does not classify an item whose type is error as tool execution; it still requires a real supplier request and the expected native terminal. The distinct top-level 404 error and turn.failed were genuine rejection evidence, not an accepted baseline timeout. They remain preserved in the original run. R2 does not add a generic error allowlist or loosen tool/network permissions.

## R3 evidence encoding correction

The second real run reached one synthetic supplier and produced the expected baseline SSE idle failure. Its evidence recorder then tried to decode a generated binary file as UTF-8. R3 decodes only the seven fixed synthetic configuration/policy paths as strict UTF-8; other regular files immediately under the private Magpie configuration directory receive only SHA256 and byte-count metadata. Symlinks and invalid text in known text inputs still fail. No transport, source patch, sandbox policy or terminal judgment changed. Both earlier failed runs remain preserved.

R4 retains strict UTF-8 decoding for the seven known synthetic text inputs and hashes generated binary evidence. Collection canonicalizes the owned root, rejects symlinked configuration ancestors and nonregular files, and runs only after owned children are reaped. It does not relax any native smoke assertion.
